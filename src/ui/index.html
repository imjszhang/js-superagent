版本历史与差异

GitHub 仓库事件来源

调整来源前，请先在本机停止后台服务。enabled 控制仓库事件接收；observe 控制是否产生观察候选；streams 选择 PR、Issue、评论、明确提及、行内审阅委托和默认分支 CI。行内审阅委托默认关闭，首次启用先记录现状。仓库凭据与允许身份由本机配置管理。

讨论订阅与判断管理

取消订阅针对整个讨论的全部工单关联，不删除工单。撤销判断会按当前状态处理；操作前核对完整记录。

事件处理与回传排障

查看为什么没接单或没回传。只读取已保存的事实，不会重新处理消息；同讨论的其他回传会单独标明。

事件与判断记录
项目协调消息

询问项目进展或协调已有工作。发送只会入队；启用持续协调并运行处理后才会回复。明确管理指令可用 /retry 工单ID、/unsubscribe 讨论ID、/dismiss 判断ID；处理时会核对所看到的版本，不允许模型扩大操作范围。

并发与故障恢复

更改前先停止执行；自动接续须有可核对证据；外部结果不明或等人回复时不会自动执行。

验证与交付

更改前先停止后台服务。验证步骤、仓库权限和允许修改的路径由本机配置管理。

界面截图验收

界面修改需要相同场景、视口和主题的修改前后截图。截图执行步骤由本机 CLI / SDK 配置。

PR 审阅动作

分别授权转为可审阅、请求审阅与解决讨论。仅对已关联且验证通过的当前提交执行；已有草稿 PR 不会自动获得新权限。

团队提示词与默认版本

保存生成新版本；可核对的团队规约在下一次正常业务轮次采用，恢复仍沿用原轮次快照。保存不会唤醒工单；无法核对的旧会话需要明确迁移。
