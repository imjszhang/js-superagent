# W4：有证据的故障接续

2026-11-02。实现未部署，后台保持停止。

## 行为

恢复设置新增 `autoResume`，默认 `false`；原有 `retryBeforeStart` 保持独立。开启后，只有适配器提供确定证据的失败才能进入自动接续：准确的原生会话与当前 runId、明确瞬时错误代码、已完成进程清理、无未知工具结果。错误文本中的 HTTP 429/5xx 不构成证据。

恢复计划保存在工单 metadata 中，包含故障 runId、原生会话、证据位置、已尝试次数、下次时间及总截止时间。恢复仍使用原生会话、工作区与授权，以新的恢复说明要求先检查已有改动和交付；不新建原始请求。退避期间不占 Worker 槽位，只在显式 run/serve 中按正常调度推进，人类反馈保持优先。

最多三次宿主恢复尝试，重开数据库不清零。原生执行及宿主后续轮次共用原轮次开始时间和执行 timeout 定义的截止时间；接续时减少本轮可用时间，不改变会话绑定指纹。耗尽次数/时间后保留待处理状态，不无限重试。

人工取消、撤权、暂停、待核对交付、新的人类说明、会话替换与明确重试都会阻止旧恢复计划继续。人工重试/替换保留历史并使旧计划失效。交付收据缺失仍走既有交付对账，不能用 Worker 恢复替代。

## 实际支持与边界

DSH rc.5 在原生 `turn/end` 明确返回 `RATE_LIMIT`、`SERVER` 或 `TIMEOUT`、且本轮没有观察到任何工具调用、没有受管任务和未确认追加输入时提供瞬时失败证据。认证错误、传输断开、工具结果不明、用户取消均不提供证据。

宿主异常退出先确认旧 owner 和 guardian 已退出；等待人、ready、普通 failed/blocked 且未收到更新输入的执行保持原状态。其余中断需要读取原生历史。统一适配器可选提供只读 `inspectRecovery()` 证明安全位置，再经同样的宿主校验接续。当前 Codex/DSH 尚未实现足够可靠的中断历史核对，因此这些真实原生中断显示 `native-history-unavailable`、要求人工检查，不冒称自动恢复已覆盖。

## 有限验证

`test/w4-recovery-runtime.test.mjs` 的七项定向检查通过：虚拟时钟退避和证据校验、保留会话并跨重开持续计数、耗尽/暂停、未知结果及新输入阻断、配置修订拒绝无迁移、只在显式处理时核对中断历史，以及旧中断任务适配器不可用时不阻塞其他任务。中断历史使用可信模拟适配器，不是真实原生历史验收。

DSH 原生错误证据另由 DSH SDK 协议 fixture 验证；实际工具不明情况被拒绝。未制造真实服务故障、未启动后台或长时间观察。
