## 同项目跨讨论关联既有工单

授权真人在当前配置仓库的 Issue/PR 中明确引用 `#123`、`owner/repo#123` 或该仓库的 GitHub Issue/PR URL 时，宿主从本项目已保存的讨论订阅发现相关工单，将工单卡及引用它的原始消息 ID 提供给协调器。协调器可以读取受限工单上下文，并用 `attach` 把选定输入交给原工单；工单 ID、会话及工作区沿用原有接续流程。

这是有界的本项目发现，不是任意工单搜索。外部仓库、伪装 URL、未知讨论、任意工单 ID、纯旁观订阅、人工终止、授权失效或已退回该输入的目标不能成为新关联目标。引用不会授予额外权限，不能借此停止所引用工单。只有明确获准的 GitHub 真人消息能发现新目标；自动推断、bot 和纯上下文输入不能借同批另一条消息的引用路由。

每批最多解析 20 条含可能引用的合格消息、合计 32,000 字节正文及 20 次引用，加入最多 8 个新目标；单个讨论最多检查 100 个订阅。无引用的普通长 Issue 和其他旁项不占发现预算，继续沿用原有研判及分页补读。超限留下明确失败，不静默裁掉可能影响路由的输入。发现过程只读本项目数据库，不为引用下载其他仓库或创建永久订阅。

模型读取及提交结果前，宿主重查评估 ID、策略版本、协调器所有权、原始消息修订及处置、讨论订阅、目标工单内容、来源和当前授权。目标被停止、撤权或改变时拒绝旧结果；批内 `attach` 必须指定 `triggerId`，新增目标必须确实由该条消息引用。

## 合批问题逐条回答

多条问题合并为一个候选时，协调器选择其中一条原始 `triggerId` 回答；其他消息可作为上下文，其余输入重新进入研判。例如先问配置默认值，再问读取路径，两条可分别读取证据并回复；一批中同时有问题和实施请求，也可先答疑，再单独接单。

`answer`、`ignore`、`unavailable` 只完成选定输入；后两者省略 `triggerId` 时仅处理第一条。单条证据不足、修订失效或没有答疑权限，不会把同批其他问题一并收尾。新增领域方法 `Engine.decideTrigger` 在同一事务内记录单条结果、释放原评估并保留其余输入及等待期间新到达的消息。原有整批 `Engine.decide` 合同保持不变，领域层没有加入 GitHub 或 DSH 依赖。

每条输入独立核对现行准入和 Worker 归属，不能继承批内最强授权。直接答案仍只允许当前获准的原始 GitHub 真人问题，复用 [0.10 答疑证明、持久 Outbox 与发送前检查](coordinator-answers-and-code-context.md)，不创建工单或 Worker。原始消息 ID 决定发送身份；重新打开项目和重放输入不会生成第二份答案。已归属 Worker 的输入继续走原有工单路径。

待发答案与同批其余请求可以分别推进。发送时结合入队快照、原始消息指纹和真实领域决策，区分“另一条请求后来新建或关联工单”与“该问题已被工单接管”。只增加讨论订阅不会误撤回先前独立答案；目标问题实际进入工单、原有旁观订阅、来源修订或授权失效仍会阻止新写入。

审计保存引用目标、来源消息、实际上下文读取及处理结果；单条决策额外保留 `triggerDecision.sourceEvalId`、该条 gate 和 owner，便于从单条结果追溯原批次。批内答案仍可在事件诊断中按 `answer` 查看。

## 升级与部署边界

schema 11 → 12 迁移声明最低写入版本 `0.11.0-alpha.0`，避免旧协调器按整批规则解释新的单条处置。旧包打开新库或继续写入时拒绝不支持的 schema；不支持新旧写者混用。升级前仍须停止项目服务、前台执行和受管子任务，再运行新版 `js-superagent --project /absolute/project upgrade` 完成核验、备份和迁移。

升级保留项目身份、工单和既有会话绑定，不自动启动后台或调整接单策略。本轮仅修改工作区源码，没有迁移生产库、安装或启动服务、发布 npm、发送真实 GitHub 评论或调用外网模型。
