## 使用变化

协调失败后，先修正原因，再明确重新入队。该操作不启动模型，随后由显式 `run` / `serve` 处理：

```bash
js-superagent --project /path/to/project coordination status
js-superagent --project /path/to/project coordination retry <event-id>
```

```js
const current = system.coordinatorStatus().settings;
system.configureCoordinator({
  workRetry: { autoRetry: true, maxAttempts: 3, initialDelayMs: 2000, timeoutMs: 120000 },
}, { expectedRevision: current.revision });
system.retryCoordination(eventId);
```

`workRetry` 与 Worker 的 `configureRecovery({autoResume:true})` 分开控制，旧设置均不自动开启。协调只对可信传输提供的短暂错误码重试，不从错误正文猜测。手动重试新建有界处理周期，累计尝试和历史保留；已完成事件返回原结果。管理面板在“协调策略与提示词”提供开关，在失败记录提供重新入队按钮。

GitHub 评论编辑无需新命令。第一次观察到旧 ID-only 记录时建立基线，不批量重放历史；之后真实修订按原授权处理。需要重新处理某条历史要求时，可在对应讨论明确提交新的更正，或由本地操作者对原工单补充要求。旧版本已读取/执行的事实保留，编辑不会撤销已发生操作。

输入详情显示“已接收，尚未确认读取”和“发送结果未知”等状态。确定未发送从 2 秒开始退避，最多三次，当前轮次结束后回归正常输入流程。发送结果未知不会因手动 retry 就直接重发；内置 Codex/DSH 即使上一轮正常结束，仍须核对未确认读取的 accepted 输入。先核对旧原生历史，无法核对时须检查原生待处理消息和已有副作用，再明确替换会话。替换保留旧投递记录，**不伪造已读**。

## 原生恢复支持范围

| 执行端 | 证据来源 | 保留限制 |
| --- | --- | --- |
| Codex `0.166.0-alpha.5.1` | 公开 `thread/read(includeTurns)`、run/turn/session/目录绑定、原生 clientId、工具终态、严格最终报告 | 只核对最新轮；未知版本、缺少新 run 锚点、活跃/残缺工具、未解释的输入、动态宿主工具或未知 item 类型均拒绝自动恢复 |
| DSH `0.2.1-rc.5` | 只读 `session.v4.jsonl`、run 锚点、user/message、inbox、成对工具结果和 job 收尾 | 不修改原生日志或队列；未消费的原生 pending 输入、未知结果、格式不符、实际启动过宿主受管任务的历史仍需检查 |

这些限制针对自动恢复；普通执行仍支持已有业务工具和受管任务。系统不会为了恢复换一个新会话冒充原会话，也不会提高原授权。已停用、取消、暂停、授权失效或新的人类要求继续阻止自动续作。重开不重置恢复预算。

DSH 规则采用单一路径：包内装配工作区规则，原生祖先/home 自动加载保持关闭。范围为 AGENTS.md；最多 128 份/64 KiB、4096 个目录，排除依赖/构建目录和符号链接，超限或不安全规则文件会明确失败。规则路径、目录作用域和 SHA-256 进入详情及追溯，正文不进入该展示快照。详见 [DSH 原生协议证据](dsh-native-reliability.md)。

5 秒是前台等待阈值，不是整项命令超时，也不是模型响应保证。普通原生 job 完成前宿主不会将任务报告为 ready；后台结果回到原 Worker。取消、超时、替换/结束由既有进程归属与原生 shutdown 收回，不新增 daemon 框架。

## 存储兼容与回退

schema 6 必须阻止旧包读取：旧调度器不理解协调事件的退避、代次和共享截止时间，忽略这些字段会重新执行正在等待的工作。因此不能只增加可忽略 metadata。

- `init`、导入、status 等查询不将旧库升级到 schema 6。普通本地入队不启动模型。
- 明确执行、保存相关配置、重试、GitHub 新事件接收等写入新语义前，检查配置/版本及旧 owner/guardian，再复用维护锁、一致性备份和原子迁移。已有活跃旧执行先等待或拒绝升级。
- 不更换原生会话，不重放历史评论，不唤醒旧失败协调记录；已有恢复计划只补上共享截止时间。
- 回退使用升级备份，先停止执行并核对新版本期间的外部动作；不要用旧包强读 schema 6。

临时 schema 5 副本已验证升级、真实上一版 Store 拒读、备份回退后可读。生产数据库未迁移，旧服务安装定义保留。
