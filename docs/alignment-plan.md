## 2. 本轮范围与保留选择

- **主范围：** GitHub 与本地 CLI/SDK；macOS 实机；已有 Codex exec 和可选 Codex app-server；单项目、单 SQLite 状态库。
- **兼容：** 旧 CLI 命令、`createProjectAgent()`、v1 Driver、工单 ID、状态类型与旧配置入口保持。新增能力通过显式版本和能力协商进入，不全局截断自定义 Driver 的 `ticket.messages`。
- **权限：** 模型工具按实际会话、派工、运行代次和当前授权检查。消息内容、摘要和模型自报身份都不能赋权。模型不直接取得完整 SDK 或交付凭据。
- **交付：** 保持本地默认；远端交付只作用于配置允许的仓库、路径和工单分支。不默认合并、强推或写默认分支。App 收件/回传与 native-gh 交付分别配置和记录身份。
- **恢复：** 不确定的外部操作默认显式核对；可证明安全的恢复单独配置。HTTP 429/5xx 或网络断开本身不能证明模型没有产生副作用。
- **会话设置：** 模型、提示词和工具合同固定版本；已有会话升级走明确的迁移入口。当前政策、撤销和资源访问检查始终实时生效，不能被旧版本固定绕过。
- **升级：** 包安装、状态迁移和高级能力启用分开。升级默认保持现有接单、并发、执行端和交付配置。
- **暂缓：** 飞书及跨渠道真实验收按用户决定暂缓。fork PR、账户 notifications inbox 逐项复刻、额外执行端、集中多项目、分布式执行、容器安全边界、Linux/Windows 服务、固定 HTTPS 和 npm 正式发布列为独立扩展。

暂缓项目不阻塞本轮 GitHub/本地目标，但不得写入已支持或已验收声明。轮询无需固定公网入口。自有代码仍为 UNLICENSED，发布准备不等同于公开发布。

## 4. 阶段 13：当前基线包补验

### 13a. 固定验收输入与证据

统一 `examples/real-*-smoke.mjs` 的安装输入：接受指定 tarball 和预期 SHA-256，先校验再安装。验收运行不能自行重新 pack；打包是独立的准备步骤。改造现有自行打包的服务脚本，且不修改已冻结的运行包。

建立统一证据格式，至少记录：源码提交和工作区是否干净、包版本/摘要/安装文件清单、Node/Codex/协议版本、配置 revision、各动作身份、场景及断言、ticket/session/assignment/run/workspace、远端 head/Actions run/回执 URL、失败及清理记录。秘密、token 和本机私钥内容不进入证据。

记录实现、模拟、真实及部署状态；失败时先保存结果再退出。验收脚本采用独立状态目录、限定命令前缀/Issue/路径，防止生产服务同时接走验收请求。测试 Issue/PR 使用唯一标记，清理只针对本次创建的对象，保留链接及最终状态。

### 13b. 三条 GitHub 验收链

1. **Issue 委托闭环。** 在限定验收分支完成包内一项可断言的代码修改；真实 Worker 修改、宿主验证、native-gh 交付草稿 PR；真实 Actions 失败及允许账号的审阅到达后，在同工单/会话/工作区修复；新 head Actions 成功，App 回传结果；关闭验收 PR 后领域工单正确完结。故障放在专用验收分支，不合入生产 main。若使用专门构造的包内 fixture，必须标为 fixture，不能冒称发现并修复了生产缺陷。
2. **新 PR 接单。** App 读取、研判、固定 head 执行和 App 评论均分别验证。本地缺少 head commit 时，先确认当前明确阻断及操作者 fetch/retry 路径有效；后续受控获取能力在 14c 实现后再验。外部修改 head 时，旧验证与旧 CI 反馈不可继续交付。
3. **默认分支 CI。** 在专用验收仓库的默认分支注入真实 Actions 失败，核对来源、匹配规则、单次接单、修复 PR、新 head 与旧事件退役。不得为此故意破坏当前生产 main。该场景依赖可用的测试仓库、App 安装及 Actions 写入范围；未具备时明确保留「待真实验收」，不使用 commit status 或假事件替代。

App 权限先只读核对，再在验收 Issue/PR 验证最小真实回传。回执记录预期 bot actor 和唯一消息标识。若仍为 403，保留失败、检查具体权限并完成针对性调整后重试原通知；禁止自动切换个人身份把 App 路径标成功。现有 App 收件、个人 gh 交付的角色划分不因测试而混淆。

### 13c. 本地基线与门槛

从同一 tarball 安装到普通无 Git/无 package.json 目录和 Git 工程，验证旧 CLI/SDK 的初始化、提交、实际修改、提问回复、取消、显式恢复、同会话续作与重开不重放。SDK 导入不启动服务；禁用 GitHub 后本地流程完整。

验收脚本增强后，若发现运行时缺陷，先固定可复现断言，再修复、重新打包并重跑受影响链路。任何一个包不能继承另一包的真实通过标签。阶段 13 是**当前基线补验**，最终完成仍须阶段 18 的新包验收。

**涉及位置：** `examples/real-*`、验收辅助模块、`docs/phase13-*-acceptance.json`；必要修复限定在具体渠道/交付模块，不借补验重做运行时。

## 5. 阶段 14：模型业务工具与按需上下文

### 14a. 统一角色工具入口

在独立适配层增加拟议 `runtime/agent-tools.mjs`，Codex app-server 的 dynamicTools 调用相同入口；SDK 和管理 API 复用相同领域命令，不复制权限判定。

| 角色 | 首批能力 | 限制 |
|---|---|---|
| Worker | 读本工单资源、确认请求、退回输入、关联话题纯上下文订阅、移除无关话题、进度/提问/最终报告 | 绑定当前 session/assignment/运行代次；只处理本派工可见输入；不能扩张授权、改设置或调用远端交付 |
| 协调者 | 读取候选及允许的关联记录、接单/附加/忽略/停止建议、传递受限上下文备注 | 当前 policy/eval/version 再校验；停止需要明确人类授权；不改代码、不获得任意 shell |
| 可信 CLI/面板 | 重评、重试、状态请求、会话替换、设置及版本迁移 | 使用独立管理身份；不因模型提出请求直接生效 |

工具调用记录稳定 call ID、参数摘要、来源身份、结果及关联领域事件。外部动作先写意图再执行；重投调用返回原结果，不重复订阅、退回、报告或发送。取消/重试后旧调用一律不能改变新派工。

区分运输接受、进入上下文、模型明确处理、业务确认四类事实。现有 `inputRead` 的证据要求不降低；业务 ack 不伪造运输或读取证据。退回保留原消息与理由，多工单共同拥有输入时按内核规则释放所有权，不能提前生成重复候选。纯上下文订阅不拥有请求，也不恢复已结束工单。

工具版本固定到新会话；既有会话保持旧工具面。提供能力检查和清楚的“不支持”结果，不通过提示词假装工具已经接通。主协调器仍只路由，不升级为另一个开发 Worker。

### 14b. 有界上下文与兼容降级

新增上下文装配器，使用「明确授权与当前目标、最近有效状态、尚未处理的增量输入、版本化资源引用」。完整历史保存在状态库；支持按需读取输入、报告、派工、决策、订阅、会话摘要和允许的来源原文。

建议初始默认预算：上下文包 32 KiB、单页 8 KiB、每轮读取总量 128 KiB/最多 16 次；按 UTF-8 字节计量，作为可信配置提供上限。授权和撤销事实不得被有损裁剪；若必要事实超预算，应解释并停止装配，不能截短后扩大范围。每份摘要标记来源 ID/版本、覆盖区间、遗漏和是否失效；摘要不代替授权或验证事实。

所有分页、记录和原始来源读取再次检查调用身份及范围；旧游标遇到内容变化须重新读取。禁止把全局 SDK `readContext()` 无范围地暴露给模型。共享备注只携带允许透露的事实，不借备注访问其他工单秘密。

app-server 通过原生工具读取资源。codex exec 保留现有入口，采用有界初始上下文和只读资源清单/快照文件；未提供原生业务工具时明确展示能力限制。必要时通过显式新会话迁移启用高级执行端，不静默切换。旧自定义 Driver 的输入形状及完整消息合同保持，新上下文合同通过版本/能力声明选择。

### 14c. 来源上下文与 PR 工作区准备

协调者可受限读取当前候选的根帖、父帖、分页讨论、明确关联工单及同仓库固定 commit 的文件/目录；先实现文本，不扩展到飞书图片读取或任意网络访问。统一截断、游标、身份和预算合同。来源数据不能覆盖角色或政策。

为同仓库 PR 增加可选的可信 head 获取：只从配置仓库获取已核对的 commit，使用受限临时 ref，拒绝任意 URL/ref 参数、fork 及会变化的分支头替代；获取前后验证 PR head、对象身份和工作区归属。不得修改用户当前分支或扩大 push 权限。默认保留显式 fetch/retry，启用该能力有独立配置及回归。

### 14d. 完成门槛

- 真实模型从超过初始预算的长历史中分页找到指定旧事实；新一轮输入大小不随完整历史无界增长。
- 真实 Worker 退回错派请求，系统只建立一个有效新候选；上下文订阅可提供事实但不授予工作权限。
- 越权工单 ID、伪造会话、授权撤销、取消后的迟到调用、过期游标和提示词注入均被拒绝；预算耗尽有可解释结果。
- 协调者读取原帖后正确接单/附加，仍无法绕过当前政策；旧 CLI/SDK/Driver 消费者通过。
- 若启用受控 fetch，从本地缺失 commit 的新 PR 完成固定 head 执行；远端 head 变化时阻断。

**涉及位置：** `context.mjs`、`context-requests.mjs`、`coordinator.mjs`、两个 Driver、`index.mjs/index.d.ts`、来源读取及 workspaces。保持 `src/core` 原样；如确有必要修改内核，单独记录来源差异并补领域测试。

## 6. 阶段 15：跨轮次后台任务、预览和子任务成果

### 15a. 任务归属与调度

将任务管理器从单次 Driver 调用提升到 assignment/runtime 生命周期。turn 结束不默认关闭仍被派工拥有的任务；completion 先持久化，再按策略请求唤醒正确 Worker。slot、任务归属与进程归属分别保存，不用 PID 存在代替身份核验。

| 情况 | 默认行为 |
|---|---|
| Worker turn 结束，普通后台任务仍运行 | 保持派工工作状态并持有槽位；允许配置的显式等待才让出槽位，唤醒前重新领取 |
| 普通任务完成 | 同一 completion 只排一个有效续作输入；暂停时保存但不启动新轮次 |
| 交人审阅 | 子 Agent 停止；只有显式登记的预览服务可保留，释放 Worker 槽位 |
| 预览服务结束 | 记录结果供下轮读取，不自行唤醒模型 |
| 工单取消/派工替换/租约到期/服务正常停止 | 回收归属进程，记录原因；不影响其他工单或用户进程 |
| 宿主崩溃 | 按 owner/guardian 核实存活状态，再清理或标中断；不盲目重放命令 |

保留总数量、活跃数、嵌套深度、总时长及单任务上限。默认后台等待上限 30 分钟，超时给出可追溯结果；重入、多个 wait 同时结束、让槽与重新领取必须无超额并发或死锁。服务停止等待任务归属清理完成。

### 15b. 人工预览租约

新增拟议 preview lease：关联 ticket/assignment/workspace/job，记录实际进程身份、loopback 地址/端口、创建/到期时间、持有人、续期和关闭动作。默认 30 分钟，可信操作者可以续期，单次最多 2 小时。仅允许预配置的预览命令；默认不暴露公网。

模型交付“可审阅预览”前，宿主核实服务实际可达，并记录当前代码摘要。提供 CLI/SDK 查看、续期、关闭入口；后续接入面板。预览继续运行不代表工单仍占执行槽，也不阻止人回复。状态过期、取消或工作区结束时链接清楚显示失效，不把旧地址当当前成果。

无 PR 的本地人工审阅采用 `waiting + attention`，保持工单和派工，审阅完成后再报告 `ready` 并结束预览；不能先用无 PR 的 `ready` 完结工单，再期望预览不被清理。已有开放 PR 的 `ready` 按现有领域规则保持待审，租约仍随真正的派工结束或到期关闭。两种路径分别验收，保持领域内核原有完结语义。

### 15c. 子任务基线与成果采纳

明确两种子任务基线：现有项目源目录副本保持兼容；新增父工作区快照模式，包含允许路径中的未提交修改，排除秘密、运行状态及缓存。记录父基线摘要、快照文件清单和子任务范围；子任务不能写父工作区。

新增受控成果采纳动作：展示子任务 diff/验证记录，检查路径、基线及父目录并发变化；只在配置授权的范围应用。冲突或过期基线返回具体差异，不自动覆盖。保存应用意图、前后摘要及可恢复记录，重新验证父工作区。默认仍需可信宿主发起；模型可提出采纳建议，不能自行绕过检查。

**完成门槛：** 真实命令跨两个模型轮次继续运行并仅唤醒一次；三个并发 Worker 与让槽保持容量正确；无 PR 本地审阅和开放 PR 审阅均可持续打开预览，且另一个工单能运行；续期/到期/取消/重启均无孤儿进程；子任务看到父快照的新改动，过期采纳和冲突正确拒绝，成功采纳重新验证。

**涉及位置：** `runtime/jobs.mjs`、调度与进程监督、app-server、`workspaces.mjs`、公共类型及 CLI；新增任务/租约记录如需数据库迁移，走阶段 16/18 的共同迁移合同。

## 7. 阶段 16：恢复、会话替换与业务健康

### 16a. 按事实分类恢复

| 故障类别 | 处理合同 |
|---|---|
| 只读同步失败、已具备幂等键的内部投递失败 | 有界自动退避；尊重 Retry-After、取消和暂停 |
| 确定尚未启动模型或外部动作 | 可配置最多 3 次重试，建议初始 15 秒退避并带抖动 |
| 模型已启动、命令中断、输出丢失 | 默认显式核对；错误码本身不触发盲目重跑 |
| commit/push/PR/comment 成功但本地收据未落库 | 按原意图和远端事实核对后补收据；无法确认则保留未知状态 |
| 会话不存在、损坏或协议不兼容 | 明确替换会话，保留工单/工作区/授权和新旧 session 关联 |

恢复前核对当前授权、暂停、远端 head、交付意图及任务所有者。固定交付目标、身份和验证基线，不能借 retry 改写尚未核实的外部操作。迟到回调用旧代次拒绝。

### 16b. 明确的会话替换

提供拟议 `session inspect/replace` CLI、SDK 和管理命令：展示替换原因、前后执行端/模型/提示词/工具版本；在受控停止旧派工后生成新会话，以有界事实包重建上下文。保留新旧会话 lineage，已处理输入不重新作为新请求，未读输入不丢失，未知交付结果先核对。

例行轮换和故障替换分开记录；禁止覆盖旧 session ID 冒充原生续用。只有明确启用且可验证的故障类型允许自动替换，否则作为人可操作的恢复项。现有默认显式恢复不因升级改变。

### 16c. 业务健康及事故记录

统一记录来源新鲜度、连续失败、执行心跳、队列最老等待、Outbox 重试、未知交付及进程清理失败。建议轮询停滞阈值为 `max(3 × pollInterval, 120 秒)`，连续失败 3 次进入事故；具体阈值由可信设置调整，实际请求耗时有独立截止时间。

状态区分 healthy/degraded/stale/disabled/paused。明确关闭的来源不参加同步健康判定；业务暂停只豁免预期的执行/业务回传积压，来源仍须持续同步，真实停滞或连续失败照常进入事故。一个事故由稳定键关联开始、升级、恢复、确认记录。默认只在本机面板显示，已有显式通知配置才可使用其渠道；同一未变化事故不重复发送，恢复转换只记录/通知一次。

**完成门槛：** 模拟边界回归加真实进程故障注入；覆盖进程仍在但轮询停滞、取消与退避竞争、模型读入后崩溃、外部写成功后断连、会话损坏替换。无重复 PR/评论/代码提交，无越权自动恢复，无丢失输入。事故与恢复记录从保存状态重启后仍一致。

**涉及位置：** effects/outbox、Driver supervisors、运行时恢复/调度、来源状态和 `management.mjs`；新增状态通过顺序迁移落库，升级失败回滚不留下半迁移。

## 8. 阶段 17：管理追溯与提示词生命周期

### 17a. 从问题定位到恢复

面板围绕待办、健康、来源、话题/事件、研判、执行和设置组织；复用既有查询与命令合同。工单详情连接 originating trigger、decision/reason/rules、mandate/policy、inputs/read/ack/handback、subscriptions、assignments/session、jobs/preview、verification/delivery 和远端结果。

提供分页时间线与原始记录入口；搜索支持工单、Issue/PR、来源链接和事件标识。增加重评、状态请求、会话替换、任务取消、预览续期/关闭、事故查看及恢复入口。动作展示适用条件和真实结果，不提供当前状态不能执行的按钮。刷新同步更新已选择详情，不能只刷新列表。

设置按来源、协调、Worker、并发、交付、恢复分组提供结构化控件；高级 JSON 可保留。宿主命令和可执行程序路径继续由可信本机配置维护，UI 不成为任意命令执行入口。涉及重启的设置说明明确；暂停不能冒充服务停止。

### 17b. 提示词分段与默认升级

保留已有 Worker/协调器编辑与历史，新增团队沟通、工单范围、交付要求等分段，以及受限的团队知识引用。记录每段默认版本/base digest、override、组装版本和来源；展示实际完整组装文本和所用变量。

默认升级提供旧默认/新默认/当前自定义三方差异，选择保留自定义或采用新默认会产生新 revision。未知字段、缺少必要占位符、超大小和保留字段覆盖直接拒绝。执行权限、政策 gate 和工具限制仍由代码执行；提示词内容不能解除。

新会话使用新版本；已固定会话继续原版本，操作者可通过阶段 16 的明确迁移采用新版本。不能一方面声明“已固定”，一方面在每次请求自动换成最新提示词。历史恢复创建新版本，保存仍核对 expectedRevision。

**完成门槛：** 真实浏览器完成事件→决策→工单追溯、提问回复、退回后的重评、失败定位与恢复、预览关闭、提示词默认升级和历史恢复；两个客户端冲突不会丢草稿；真实模型使用目标版本，旧会话仍保留原版本；同源/身份保护、脱敏与分页限制保持。

**涉及位置：** `management.mjs`、`src/ui/*`、角色配置/提示词注册和只读查询；界面操作不独立重写领域规则。

## 9. 阶段 18：最终同包验收、部署及交付

### 18a. 冻结最终候选包

功能与修复提交后，从明确提交构建一次候选包，记录提交/包摘要/运行文件清单。所有真实验收和部署都从该包安装；脚本运行前验证摘要。候选包可以使用下一 alpha 版本，版本号在冻结时确定。

阶段 13 的证据保留为基线。最终包必须重跑 Issue→PR→真实 Actions/审阅修复→App 回传主链路、App 新 PR 路径，以及已实现的新工具/上下文/任务/恢复关键场景。候选包的运行文件发生变化则重新冻结；完整主链路在最终包上再跑，不能用“修改很小”继续引用旧结果。仅证据文档更新与运行文件变更分别记录。

### 18b. 安装、迁移和回退

- 在普通目录与 Git 工程验证 tarball 的旧 CLI/SDK/类型消费者、新高级接口和静态资源；确认不依赖 DSH、不打包本地状态或秘密。
- 迁移覆盖当前 DB3 到本轮目标版本；版本由实际新增状态决定。新包验证旧配置，旧包拒绝更高 schema。备份需 SQLite 一致性和摘要核验。
- 在隔离项目**实际安装旧包并打开匹配的升级前备份**，验证待处理工作和暂停恢复，不仅生成恢复候选。升级后的远端动作以清单核对，不能恢复旧游标后盲目重放。
- Node 22.13.0 执行安装/类型/关键迁移及恢复回归，当前 Node 24 执行完整测试和真实场景；有不兼容再调整声明，不未经验证扩大平台承诺。

### 18c. 持续服务与生产切换

隔离服务进行至少 30 分钟、至少 60 次成功轮询的观察；必要时延长以覆盖故障窗口。期间包含超过 180 秒的 Worker、后续反馈、业务暂停、停止期间补收、进程异常退出及恢复。记录事件落库延迟、有效重复数、积压年龄、事故与恢复。正常网络下反馈目标为两个轮询周期加 5 秒内落库；这是受控验收阈值，不是公网 SLA。

切换前保存配置 revision、服务定义、业务计数、待核对外部意图、包和一致性备份；明确活动任务的等待/停止方式，确认旧所有者退出，再安装固定路径。核对唯一服务和调度所有者、暂停保留、输入/会话/工作区及远端收据完整。切换后观察至少 10 个正常同步周期，并跑一个限定范围新任务。

默认部署保留单 Worker、明确接单及当前交付配置。为 app-server/工具、多 Worker、observe 和 draft-pr 分别提供可审阅的配置档案与回退点；按用户已选择的使用范围逐项启用。生产主动 `auto` 只启用已验收规则，不能把安装升级视为扩大授权。无需重复询问已经明确授权的常规实施/修复；新增外部资源、授权范围或公开发布才列实际依赖。

### 18d. 最终交付

更新 README、运行合同、支持矩阵、变更记录和实施状态；为每项列清实现、真实验证及部署状态。保留各阶段验收脚本、机器可读证据及清理结果，给出安装/配置/故障恢复最短操作路径。

本轮完成需要阶段 13–18 必选门槛通过；默认分支 CI 若仍缺真实资源须明确列为未完成，不能用“总体完成”掩盖。飞书、其他系统服务、整机重启、HTTPS 和 npm 发布按支持矩阵继续标明边界，不妨碍已限定的 macOS GitHub/本地子集单独交付。

## 11. 工程拆分、依赖与完成记录

建议保持可单独审阅的提交单元：13 验收设施与基线问题修复；14a 工具权限合同、14b 上下文/来源及 Driver 桥接；15a 持续任务/预览、15b 子任务采纳；16a 恢复/会话、16b 健康；17 面板/提示词；18 发布候选与记录。每单元包含必要回归和使用文档，不进行无关的大规模文件重排。
